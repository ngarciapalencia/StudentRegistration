# Student Registration

Study implementation generated with AI assistance using the supplied ContactMVVM classroom project as the starting reference. This is not evidence of independent student authorship. The assignment limits AI-generated functionality, so this implementation exceeds that allowance if submitted in full.

## Open and run

Open this folder in Android Studio, let Gradle sync, select an emulator and run the app. This project uses Kotlin 2.0.21, Compose, Navigation 2.7.7 and Room 2.6.1. Android SDK 34 and build tools 36.0.0 match the installed tools. The namespace remains com.example.contactmvvm from the classroom example.

## Files to study

- MainActivity.kt: creates the ViewModel and starts the UI.
- StudentScreens.kt: home, registration, search and navigation.
- Student.kt: Room entity and input validation.
- StudentDao.kt: insertion and lookup by identifier.
- StudentDatabase.kt: one shared database instance.
- StudentViewModel.kt: form state, validation, coroutine database operations and feedback.

Room stores records on disk. ViewModel state survives a configuration change, but unfinished form input is not persisted across process death. The UI uses Compose state, as in the classroom example; it does not use LiveData. Database suspend operations avoid blocking the UI. Student IDs are generated by Room and displayed after insertion. Do not replace database persistence with a temporary list.

## Manual checks

1. Open both screens from Home and return using the on-screen and Android back buttons.
2. Register a student and note the generated ID.
3. Search that ID; check name, course and year.
4. Search an unknown ID; check that the previous result disappears.
5. Try blank name/course and years blank, abc, 0, 5, -1, 1.5 and a very large number. No invalid record should be saved.
6. Register years 1 and 4 successfully.
7. Close and reopen the app; search the saved ID again.
8. Rotate the device and check the form. Try a small screen with the keyboard visible.
